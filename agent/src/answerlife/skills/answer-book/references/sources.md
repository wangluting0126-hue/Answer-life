# 出处要能被找到

## 本包实际有什么

保留用户 v0.1 提供的 57 条候选、6 部作品与原始核验表。核验表是上游材料的声明，不能据此宣称本版本已重新逐条校订。每条增加 `provenance: supplied-v0.1`。本次发现 `apology-30e` 混入译本边栏概要，已标记 `blocked: true`，渲染器拒绝引用；保留原记录以便追溯。56 条未禁用候选不代表 56 条均经本次全面重核。

详见 [../quotes/核验说明.md](../quotes/核验说明.md)。新页面中不要写“本次全部验证通过”。没有联网时仍可离线读取随包记录，并显示其实际核验口径。

## 三种使用情况

| 情况 | 显示 | 规则 |
|---|---|---|
| 库中条目 `verified is true` 且未 blocked | 原文、作品位置、可点击来源、随包核验记录 | 用 ID 注入原文，不手填；有疑问先查上下文 |
| 现代书有可靠理解但没有逐字原文 | 书意转述、书名、未引原文 | 不加原话引号，不给页码，不仿拟作者为用户下指令 |
| 无法确认观点归属或没有适切书 | 本页的另一个可能 / 本页借读 | 不挂作者与书名，不伪装古典权威 |

用户给的照片或文本只是“用户提供”，不是 `verified` 的快捷通道。本版本不自动将私人现代书页永久写入公版库。可以在当次对话核读和短引，并标其真实版本情况；若需要制作可渲染原文条目，先单独确认来源、范围和版本，再开发相应导入流程。当前渲染器只支持现有公版库与纯转述模式。

## 核对的不只是字面

维基文库页面可能把边栏、编辑注释、译者注与正文混在一起。网页全文能搜到并不等于角色说过或作者写过。核对内容所属层次、说话者、篇章定位和上下文。

《申辩篇》是柏拉图的文本，苏格拉底是文本中的发言者；Jowett 是英译者。《哈姆雷特》台词要看角色和场景，不把波洛涅斯的训诫等同莎士比亚个人主张。古籍不确定年代不造精确年份，也不把文句和某次生平事件绑定。

`context_note` 是每页必填的“原意与本次借读”。它不能替代核验，但能显露解释的跳跃。现代判据、数量阈值与行动均由本次设计，不写成原书规则。

## 技术边界

渲染器能拒绝无 ID、未知 ID、未 verified、blocked 的库引文，能拒绝原文覆盖字段，并转义全部输入文案。它无法判断自由文案中的历史事实、转述是否准确、未标出的名言是否被伪造。这部分必须在出页前读源核对。不要使用“结构上不可能伪造”的宣传语。

## 手工维护

新条目需记录实际可访问文本、版本、正文定位、原文与复核日期。保留原始字形和标点；空白归一只用于比对，不悄悄改写引文。异体、繁简和章号差异写在核验记录里。核验后才能设 `verified: true`；发现问题设 `blocked: true` 并写原因。每次修改运行 `verify.py`，并检查所有引用该 ID 的示例。
