# 让对话产生信息，而非只产生问题

## 从用户此刻的需要出发

“找不到工作怎么办”优先需要实际帮助。“我投了很多，觉得自己什么都不行”还包含对自我判断的困扰。先回应已经表达的需要，再考虑书。不能把现实瓶颈自动心理化，也不要用一本古籍跳过材料与条件检查。

## 保留一份简洁依据

在当前对话上下文维护四类摘要，不要求落盘、不收集隐含人格：

| 类型 | 怎么记录 | 怎么用 |
|---|---|---|
| facts | 用户原话支持的事实、数字、阶段、尝试 | 回应必须用到至少一条相关事实 |
| possibilities | 一到两个可能解释；标记待验证 | 解释需要能被推翻，不能给动机定性 |
| unknowns | 真正影响选择的缺口 | 不按固定表单补齐所有字段 |
| next_check | 最能区分解释的一条信息或一个动作 | 这条信息的不同答案，应导致不同下一步 |

这些是可向用户说明的简短依据，不是让模型暴露逐步思维链。无需打“87% 置信度”等没有校准的数字。

例：用户明确说“同一份简历投产品、运营、咨询，20 份都没面试”。可说通用材料的匹配度值得先检查；不能说“已经证明你定位不清”。反例是材料其实逐项符合要求，但岗位状态、申请条件或时间窗另有影响。下一条信息可以是选一个目标岗位、对照其真实要求，而不一定是索取整份简历。

## 追问值不值得

发问前检查：不同回答会不会改变行动？用户前文是否已回答？能不能直接给分支并让他先做？

信息收益按实际判断，不假装计算了数学上的信息增益。公司、岗位、全职/实习与申请阶段可能一次已经给全；不要分别再问四轮。两轮都只有补资料时，先提供一次具体判断或动作，再决定是否继续。无素材时可以问事实，不为满足规则虚构洞察。

## 短回复与误解恢复

“第二种”回指上一个选项；“都有”保留范围广这一事实，但不是已证实的散投；“FT”只展开全职，不补造毕业年、地区和学历。识别错了，简短改正，再改对应的判断与动作，不从头播放问卷。

用户说“不是这个意思”，先复述他纠正的目标，撤回失效解释。用户要今天能做什么，就给今天能做的；书页可以放后面。没有原文适配，使用转述或本页提出的反例，不硬匹配主题词。

## 出页条件与停止条件

知道当前问题、至少一条事实，能提出一个可逆、可观察的动作，就可以交付暂定页。用户指定直接出页时不再加审批。页面应回答：现在能判断什么、还不能判断什么、下周拿什么结果回来。

单一实验缺乏结果时，继续换书通常不会增加信息。先区分没开始、做了但没反馈、反馈否定假设、反馈混合；承认原解释可能错。复盘有效结果也应允许用户保持现状，不假定每次都必须改变。

## assessment 示例

```json
{
  "facts": ["用户说同一份材料投了三个岗位方向", "20份申请尚无面试回应"],
  "possibilities": ["通用材料与某一岗位的匹配表达可能不足，尚未检查"],
  "unknowns": ["实际职位要求与已投简历内容", "申请地区与投递时间"],
  "next_check": "选一份实际职位描述，检查三项要求是否各有经历证据"
}
```

assessment 只保留对判断有用的信息；不放隐私原件、账户凭据或无关个人细节。它不是推理正确性的自动证明。
